about=NoWires is a QGIS plugin for radio propagation analysis powered by NTIA's Irregular Terrain Model (ITM), using the Qt 6 / PyQt 6 runtime bundled with QGIS 4. It provides point-to-point path loss analysis with Fresnel zone visualization, batch P2P analysis (one-to-many and many-to-one), unified Coverage Analysis heatmap prediction with raster-derived range metrics, Coverage Comparison producing delta rasters, and contour line generation. Clutter correction supports simple per-category losses and advanced mode (saalos vegetation model, ITU-R P.2108 for built/rural). DEM data is automatically downloaded from the Copernicus GLO-30 dataset hosted on AWS Open Data. The plugin bundles the ITM library from https://github.com/tedaks/pyitm and adapts code from https://github.com/tedaks/nowires and https://github.com/tedaks/ContourLines. See NOTICE.md for attribution and third-party licensing details.

    - Fix PicklingError on Windows multiprocessing after the v1.5.5 pythonw.exe switch made the gate succeed and exercised a latent bug. _coverage_executor captured _init_cov_pool and _itm_worker_batch by name at module import time via `from .coverage_pool import ...`; if NoWires.coverage_pool was later replaced in sys.modules (QGIS plugin reload, Plugin Reloader, any importlib.reload of just that file), the cached references diverged from sys.modules["NoWires.coverage_pool"].<name> and pickle's identity check raised `_pickle.PicklingError: Can't pickle <function _init_cov_pool at 0x...>: it's not the same object as NoWires.coverage_pool._init_cov_pool`. Fix: move the `from .coverage_pool import _init_cov_pool, _itm_worker_batch` inside execute_coverage_tasks, so the references handed to ProcessPoolExecutor are exactly the ones pickle finds via getattr(sys.modules[fn.__module__], fn.__qualname__).
    - Change the multiprocessing-fallback diagnostic from feedback.pushInfo to feedback.pushWarning and include the exception type/message. Previously the underlying error was emitted only via Python logger.warning, which can silently drop messages on GUI-subsystem QGIS builds with a None-stream StreamHandler — making the failure mode invisible to users. The QGIS Processing log panel now shows the actual cause, so future regressions are self-diagnosing.
    Version 1.5.5
    - Fix coverage multiprocessing silently falling back to sequential on macOS. Three distinct bugs all surfacing as 'Multiprocessing unavailable'. (1) Shared-memory name too long for macOS PSHMNAMLEN=31: truncated UUID hex suffix from 20 to 16 chars. (2) Cross-process cancel signal removed entirely; multiprocessing.Event() failed under spawn, Manager().Event() failed with EOFError on macOS QGIS. Cancel now relies on main-thread break between batches (~320ms worst case). (3) QGIS-bundled python3.12 has sys.prefix baked to CI builder path; spawned workers couldn't find stdlib ('No module named encodings'). configure_macos_multiprocessing now sets PYTHONHOME=sys.prefix so workers inherit a working stdlib pointer. Added _can_spawn() validation and NOWIRES_PYTHON_EXE env override.
    - Measured 4-6× speedup on the in-container benchmark (~7k px/s → 31-48k px/s); macOS users will see equivalent gains.
